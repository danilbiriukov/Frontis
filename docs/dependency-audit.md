# Уязвимости зависимостей npm

Frontis запускает `npm audit` через официальный плагин Code PushUp `js-packages`. Для проверки нужен `package-lock.json` или `npm-shrinkwrap.json`. npm отправляет сведения о зависимостях реестру из настроек проекта. [Документация npm audit](https://docs.npmjs.com/cli/v11/commands/npm-audit/)

В `report.json` аудиты `js-packages/npm-audit-prod` и `js-packages/npm-audit-dev` хранятся вместе с результатом проверки устаревших пакетов. Для двух проверок действуют отдельные настройки `modules.audit` и `modules.outdated`, включая тайм-ауты. Если один запуск завершился с ошибкой, аудиты второй проверки сохраняются.

В `result.json` находка содержит уязвимый пакет, группу `prod` или `dev` и исходный уровень при наличии. Для транзитивной находки сохраняется указанный плагином пакет из цепочки зависимостей. Если npm сообщает об исправлении, в `fix` сохраняется его доступность, а при наличии рекомендации также пакет, версия и признак несовместимого обновления.

Уровни `critical` и `high` дают высокую важность, `moderate` среднюю, `low` и `info` низкую. Ноль уязвимостей появляется после успешного аудита. Недоступный реестр и автономный режим npm дают причину `registry-unavailable`, отсутствующий lock-файл даёт `no-npm-lockfile`.
