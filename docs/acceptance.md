## Как повторить

1. Собрать Frontis через `npm ci` и `npm run build`. Запомнить абсолютный путь к `dist/cli.js`.
2. Клонировать каждый репозиторий и переключиться на указанный коммит. В Axios и Expense Tracker React выполнить `npm ci --ignore-scripts --no-audit --no-fund`. В Anime.js выполнить `npm install --ignore-scripts --no-audit --no-fund`. На теге v4.3.6 `npm ci` выдаёт `EUSAGE` из-за отсутствующих записей платформенных пакетов Rollup. SHA-256 обновлённого lock-файла равен `B36047B1F934404D60354DB274A0AE6048331356E877FEFD0BF264D4C1ADAD05`.
3. Для Anime.js оставить `export default {};`. Для Expense Tracker React задать `export default { buildDir: 'build', outFile: '.frontis/report with spaces.html' };` и выполнить `npm run build` с `NODE_OPTIONS=--openssl-legacy-provider` для Webpack 4. Для Axios использовать команды из раздела проверки покрытия.
4. В корне проекта дважды выполнить `node <абсолютный путь к dist/cli.js> run`. Сравнить `runAt` в `result.json` и время записи HTML. Проверить `report.json`, `no-data.json` и карточки в браузере. На повторном запуске проверить открытие отчёта через `--open` или `frontis open`.

## Axios. Покрытие, тесты и анализ кода

В копии Axios выполнены `npm run build` и `npm install --no-save --ignore-scripts --no-audit --no-fund @vitest/coverage-v8@5.1.0`. Манифест и lock-файл остались прежними. Конфигурация запуска Vitest с покрытием одного файла выглядит так.

```js
export default {
  testCommand: 'npm run test:vitest:unit -- tests/unit/helpers/isAxiosError.test.js --coverage.enabled=true --coverage.include=lib/helpers/isAxiosError.js --coverage.reporter=lcov --reporter=default --reporter=json --outputFile.json=.frontis/test-results.json',
};
```

Прямой запуск той же команды с отдельными каталогами для JSON и LCOV дал 4 пройденных теста и покрытие 1 строки из 1. Frontis показал те же 4 теста и 100% строк. Покрытие относится к `lib/helpers/isAxiosError.js` в выбранном наборе тестов.

Прямой `node ./node_modules/prettier/bin/prettier.cjs . --list-different --ignore-unknown` вывел 498 путей. Два из них относятся к HTML и JSON в `.frontis/`, которые Frontis исключает. Остальные 496 совпали по счётчику с Frontis. Проект использует ESLint 10.14.0. Прямой `node ./node_modules/eslint/bin/eslint.js . --format=json` обработал 260 файлов и сообщил о 4 ошибках и 111 предупреждениях. Frontis указал `eslint-unsupported`, а данные Prettier сохранились в карточке качества кода. [Поддерживаемые версии ESLint](code-quality.md)

Для прогона с поддерживаемой версией выполнено `npm install --no-save --ignore-scripts --no-audit --no-fund eslint@9.39.5 @eslint/js@9.39.5 @vitest/coverage-v8@5.1.0`. Прямой ESLint 9 обработал 264 файла и выдал 4 ошибки, 115 предупреждений и 0 ошибок разбора.

## Методика сравнения для #34

Предложение для согласования перед замером. На каждом из трёх коммитов подготовить отчёты Frontis и Code PushUp 0.126.4 с одинаковым набором проверок и входными данными. Попросить разработчиков назвать до трёх первых действий по отчёту и обосновать их данными аудита. Чередовать порядок отчётов. Засекать активное время от открытия отчёта до записи решения.

Предлагаемый порог эффекта — медиана активного времени до 50% от времени с Code PushUp или минимум одна дополнительная подтверждённая значимая находка в двух проектах из трёх. Значимая находка подтверждается прямым запуском инструмента и требует исправления либо объясняет сбой обязательной проверки. Замер эффекта и сверка с мнением разработчиков требуют согласования порога и участия разработчиков.
