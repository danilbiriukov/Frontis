# Контракт сборщика Frontis

`Collector<TData>` принимает `CollectorContext` с абсолютным путём `projectDir` и необязательным `signal` для отмены. Настройки конкретного инструмента передаёт фабрика сборщика при его создании. Сборщик может вернуть результат сразу или через `Promise`. Он работает отдельно от Code PushUp и использует переданный путь при чтении файлов и запуске команд.

| `status` | Когда возвращать | Данные |
| --- | --- | --- |
| `ok` | Проверка выполнена, в том числе без нарушений | Факты инструмента в `data` и список `findings`, который может быть пустым |
| `no-data` | Нет инструмента, настроек или входных данных, например не найдено ни одного файла для проверки | Стабильный `code`, причина `reason`, подсказка `action` |
| `error` | Инструмент завершился со сбоем или вернул повреждённый результат | `code`, `reason`, `action` и при наличии исходная ошибка в `cause` |

У находки есть код типа (`unused-export`), сообщение и уровень инструмента (`error`, `warning`, `info`). Если известно место, укажите `source.file` от корня проекта и `source.position` с номером строки и, при наличии, столбца. Нумерация начинается с 1. Для файловой находки без номера строки достаточно `source.file`.

## Подключение к Code PushUp

В обёртке задайте метаданные стандартного `PluginConfig`: `slug`, `title`, `icon` и `audits`. Назначьте `runner: createCollectorRunner(context, collect, toAudits)` и добавьте плагин в `plugins` обычной конфигурации Code PushUp. При запуске движка из корня проверяемого проекта относительные пути находок сохраняются в отчёте.

`toAudits` преобразует успешный результат в `AuditOutput[]`. Он возвращает один результат на каждый заявленный аудит, включая нулевые значения. Чтобы передать находку в `details.issues`, используйте её `message`, `severity` и `source`. По коду типа можно распределить находки по аудитам. При `no-data` и `error` функция запуска выбрасывает `CollectorRunError` с причиной в `error.result`. Необработанное исключение сборщика передаётся вызывающему коду.

Идентификатор своего плагина начинается с `frontis-` и отражает назначение, например `frontis-knip`. Идентификатор аудита описывает измеряемый показатель, например `unused-exports`. Используйте строчные латинские буквы, цифры и дефисы. Идентификатор аудита уникален внутри плагина и совпадает в метаданных и результате. Сохраняйте пару идентификаторов при изменении заголовков, версий инструмента и путей проекта.

[Плагин-заглушка](../test/collectors.test.js) добавлен напрямую в конфигурацию движка 0.126.4. `npm test` из Git-репозитория проверяет по `reportSchema` аудит с находкой и успешный нулевой результат. Отдельные тесты проверяют передачу `no-data` и `error`.
