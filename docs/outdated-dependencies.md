# Устаревшие зависимости

`frontis run` проверяет установленные зависимости проекта npm. В `report.json` сохраняются официальные аудиты `js-packages/npm-outdated-prod` и `js-packages/npm-outdated-dev`. В `result.json` видны текущая и целевая версии пакета, группа и тип отставания. Мажорные обновления выделяются в оценке отдельно. Предварительные версии учитываются в соответствующей группе major, minor или patch.

Для доли Frontis берёт установленные пакеты с сопоставимыми версиями из `dependencies` или `devDependencies`. Локальные ссылки, Git-зависимости, npm-алиасы, необязательные зависимости и пакеты без установленной версии в знаменатель не входят. Доля равна числу устаревших пакетов, делённому на число сопоставимых пакетов той же группы, и хранится в процентах.

Frontis использует реестр из настроек npm. Если `npm outdated` пропустил пакет, Frontis проверяет опубликованную версию через `npm view`. Для проверки используется временный кэш текущего запуска. Ноль и доля появляются только после подтверждения данных всей группы. Если одна группа недоступна, в результате остаются подтверждённые находки и доля другой группы, когда её удалось рассчитать. [npm outdated](https://docs.npmjs.com/cli/v11/commands/npm-outdated/) · [npm view](https://docs.npmjs.com/cli/v11/commands/npm-view/)

`productionState` и `developmentState` принимают значения `verified`, `empty` и `unconfirmed`. Если пригодных аудитов нет из-за недоступности метаданных, диагностика модуля содержит `registry-unavailable`. Поддержка других менеджеров пакетов относится к проверке совместимости [#35](https://github.com/danilbiriukov/Frontis/issues/35).
