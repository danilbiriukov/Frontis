# Места использования отстающих пакетов

`createImportMapCollector({ packages, limit })` показывает, какие файлы проекта импортируют наиболее отстающие зависимости. Карта помогает найти код для проверки перед обновлением. В общий балл она не входит, поэтому находок нет, только `data`.

`packages` — список `{ name, current, latest }` из проверки устаревших зависимостей [#22](https://github.com/danilbiriukov/Frontis/issues/22). `undefined` означает, что сведений нет. Из списка выбираются `limit` (по умолчанию 5) пакетов с наибольшим отставанием: сначала по разнице major, при равном major по minor, затем по patch. Пакеты с одинаковым отставанием упорядочены по имени. Пакеты с версией не в формате `x.y.z` идут последними.

Исходники берутся из `git ls-files --cached --others --exclude-standard`, то есть с учётом `.gitignore`. Вне Git каталоги обходятся без `node_modules`, `dist`, `build`, `coverage` и скрытых папок. Просматриваются файлы `.js`, `.jsx`, `.ts`, `.tsx`, `.mjs`, `.cjs`, `.mts`, `.cts`, `.vue`, `.svelte` и `.astro`.

Учитываются `import … from`, `export … from`, `import '…'`, `import('…')` и `require('…')`. Импорт засчитывается пакету, если спецификатор равен имени или начинается с `имя/`. Поэтому `lodash/fp` относится к `lodash`, а `lodash-es` нет. Импорты внутри комментариев и строк не отличаются от настоящих. Импорты в каждом файле сохраняются с номером строки и полным спецификатором, порядок стабилен.

| `status` | `code` | Когда |
| --- | --- | --- |
| `ok` | | Список пакетов получен, в том числе пустой |
| `no-data` | `no-outdated-data` | Сведений об отставании нет |
| `no-data` | `no-sources` | В проекте нет исходных файлов |

Порядок обновления и оценка ломающих изменений относятся к следующему этапу.
