# Проверки качества кода

`frontis run` запускает ESLint и Prettier отдельно. Их можно отключать независимо через `modules.lint.enabled` и `modules.prettier.enabled`. В `result.json` результаты обеих проверок входят в показатель `codeQuality`. Если одна проверка пропущена, показатель помечается как неполный, а находки второй проверки остаются в оценке и рекомендациях.

## ESLint

Frontis ищет файл настроек ESLint в корне проекта и использует ESLint из зависимостей проекта. Проверены плоская конфигурация и `.eslintrc.json` на ESLint 9.39.5. Адаптер также принимает ESLint 8 начиная с версии 8.46 для конфигурации `.eslintrc`. Для плоской конфигурации нужен API `loadESLint`. Список имён файлов описан в [настройках движка](engine-config.md).

ESLint проверяет каталог проекта с учётом исключений из конфигурации. Из одного вызова `lintFiles` Frontis получает проверенные файлы, сообщения и ошибки разбора. Официальная фабрика Code PushUp 0.126.4 формирует метаданные правил, а её преобразователь сохраняет идентификаторы аудитов, в том числе разные идентификаторы для разных параметров правила. [Node.js API ESLint](https://eslint.org/docs/v9.x/integrate/nodejs-api#eslintlintfilespatterns)

В `report.json` рядом с аудитами правил записываются `eslint/frontis-checked-files` и `eslint/frontis-parse-errors`. В первом хранится число файлов и таблица из десяти наиболее частых правил. Нарушения вариантов одного правила суммируются. Во втором хранятся ошибки разбора с путём и строкой, если ESLint её сообщил. Прочие сообщения без идентификатора правила при наличии попадают в `eslint/frontis-eslint-messages`.

| Код | Причина |
| --- | --- |
| `no-eslint-config` | В корне проекта нет файла настроек |
| `eslint-not-installed` | ESLint не найден из каталога проекта |
| `eslint-unsupported` | Версия ESLint не поддерживает выбранный формат |
| `no-files` | ESLint не проверил ни одного файла |
| `eslint-coverage-unconfirmed` | По данным запуска нельзя подтвердить проверку файлов |
| `eslint-failed` | Проверка прервалась из-за ошибки инструмента или настроек |

При успешной проверке хотя бы одного файла в `checks[].facts` доступны `checkedFiles`, `errors`, `warnings` и `parseErrors`. Ошибки разбора входят в общий счётчик ошибок. Топ правил хранится в `checks[].details.rules`.
