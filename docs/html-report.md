# Локальный HTML-отчёт Frontis

Генератор в `src/report/` строит HTML из оценки в `result.json` и причин пропусков. Исходные аудиты доступны в `report.json`. Файл открывается с локального диска и не требует подключения к сети.

По умолчанию отчёт сохраняется в `.frontis/report.html` (или по пути из `outFile` в `frontis.config`).

---

## 1. Режимы работы

### Стандартный отчёт (валидный запуск)
Формируется при наличии хотя бы одного валидного аудита.
- **Шапка**: имя и версия проекта, время запуска, первые семь символов коммита и ветка Git при наличии. Поля расположены в одной колонке. Полный хэш доступен при наведении. Без хэша выводится «Коммит недоступен».
- **Оценка проекта**:
  - Итоговый балл (0–100), шкала, цветовая зона (`green` ≥ 90, `yellow` 60–89, `red` < 60) и её текстовая расшифровка.
  - Если модулей с данными меньше трёх (`known < 3`), выводится прочерк `—` и указание на недостаток данных.
  - Охват оцениваемых показателей (`known/total`).
- **Четыре счётчика статусов**: раздельные блоки для «Действий не требуется» (`ok`), «Запланировать» (`plan`), «Исправить» (`fix`), «Нет данных» (`no-data`).
- **Таблица рекомендаций**: упорядочена по важности (`high` → `mid` → `low`) с текущим значением, целью и описанием действия.
- **«Показатели без данных»**: причины и следующие шаги для пропущенных и частично выполненных проверок.
- **Карточки показателей**:
  - Статус и ключевая метрика. В карточке покрытия шкала показывает процент строк, порог и цель из конфигурации.
  - Пометка «Неполные данные», если часть проверок пропущена. Подтверждённые результаты остаются видны.
  - Раскрываемые списки крупнейших файлов сборки и ссылки на разделы с деталями проверок.
  - Источник данных и время, измеренное от запуска до завершения проверки. Для составной карточки время складывается из замеров её проверок. Если замеров нет, время не выводится.
- **Находки по проверкам**: у устаревших зависимостей, уязвимостей, ESLint, Prettier, покрытия LCOV и итогов Jest или Vitest свои разделы. Раздел ESLint также показывает частые правила. В разделах покрытия и тестов видны доступные метрики и отклонения.
- **Места использования отстающих пакетов**: таблица с текущими и доступными версиями. Список импортов с путями и строками раскрывается для каждого пакета.
- **Подвал**: версии Frontis и Code PushUp, общее время и ссылка на документацию.

### Диагностический отчёт (полный отказ, код выхода 2)
Формируется при отсутствии пригодных аудитов.
- Общий балл отсутствует.
- Сводка и таблица причин по модулям: модуль, код сбоя, причина, следующее действие и относительный путь к журналу при наличии (в `.frontis/logs/`).
- Карточки показывают причины пропуска или сбоя, когда у Frontis есть сведения о них.

---

## 2. Безопасность и автономность

1. **Экранирование**. Пути, имена пакетов, правила и сообщения инструментов выводятся как текст через `escapeHtml`. HTML-отчёт обходится без скриптов.
2. **Объём подробностей**. В каждом списке HTML отображается до 10 находок. Полные аудиты сохраняются в `.frontis/report.json`.
3. **Просмотр без сети**. Стили встроены, шрифты системные. Браузер обращается к GitHub только при переходе по ссылке на документацию.
4. **Чтение с телефона и с клавиатуры**. Карточки перестраиваются под ширину окна. Широкие таблицы прокручиваются внутри блока, подробности раскрываются клавишей Enter.
5. **Оформление**. Отчёт использует светлую палитру макета при любой теме системы.

---

## 3. Открытие в браузере

- Отчёт открывается в браузере по умолчанию только при флаге `--open` (`-o`) в CLI или при `open: true` в `frontis.config`.
- Открытие работает кроссплатформенно:
  - Windows использует файловую ассоциацию через PowerShell `Start-Process`.
  - macOS: `open <url>`
  - Linux: `xdg-open <url>`
- При диагностическом запуске (код выхода 2) отчёт автоматически не открывается, путь выводится в консоль: `Диагностический отчёт: .frontis/report.html`.
- При сбое системной команды Frontis выводит путь к сохранённому файлу. `frontis open` возвращает код 2. Для `frontis run --open` код определяется результатом аудита.
