# Локальный HTML-отчёт Frontis

HTML-отчёт формируется автономным генератором в `src/report/` на основе `report.json` (#12) и `result.json` (#19). Файл создаётся без внешних сетевых зависимостей и открывается с локального диска (`file://`).

По умолчанию отчёт сохраняется в `.frontis/report.html` (или по пути из `outFile` в `frontis.config`).

---

## 1. Режимы работы

### Стандартный отчёт (валидный запуск)
Формируется при наличии хотя бы одного валидного аудита.
- **Шапка**: имя проекта, версия, ветка Git (при наличии), хэш коммита (при отсутствии — `Коммит недоступен`), дата и время запуска с длительностью.
- **Оценка проекта**:
  - Итоговый балл (0–100) с цветовой зоной (`green` ≥ 90, `yellow` 60–89, `red` < 60) и текстовой расшифровкой.
  - Если модулей с данными меньше трёх (`known < 3`), выводится прочерк `—` и указание на недостаток данных.
  - Охват оцениваемых показателей (`known/total`).
- **Четыре счётчика статусов**: раздельные блоки для «Действий не требуется» (`ok`), «Запланировать» (`plan`), «Исправить» (`fix`), «Нет данных» (`no-data`).
- **Таблица рекомендаций**: упорядочена по важности (`high` → `mid` → `low`) с текущим значением, целью и описанием действия.
- **Таблица причин «Нет данных»**: сводка причин и рекомендуемых действий для проверок без данных.
- **Карточки показателей**:
  - Заголовок, значок и бейдж статуса.
  - Пометка `Неполные данные` для составных показателей (`codeQuality`, `coverage`), если часть проверок не вернула данных.
  - Список находок (до 10 записей с уровнем, файлом, строкой и сообщением).
  - Сводные факты, крупнейшие файлы (для сборки) и частые правила (для линтера).

### Диагностический отчёт (полный отказ, код выхода 2)
Формируется при отсутствии пригодных аудитов.
- Общий балл отсутствует.
- Диагностический баннер с предупреждением.
- Таблица причин отсутствия данных по всем модулям: плагин, код сбоя, причина, рекомендуемое действие и ссылка на лог-файл (в `.frontis/logs/`).

---

## 2. Безопасность и автономность

1. **Экранирование XSS**: все строки из проверяемого проекта (пути к файлам, имена пакетов, правила и сообщения инструментов) экранируются через `escapeHtml`. Защита от раннего закрытия тегов `</script>` обеспечивается через `safeJson`.
2. **Ограничение размера**: списки находок ограничены 10 записями на список. Исходные JSON-файлы в `.frontis/` сохраняют полный набор данных. Размер итогового HTML-файла строго до 1 МБ.
3. **Zero-network**: стили встроенные (`<style>`), системные шрифты (`system-ui`, `-apple-system`, `Segoe UI`), отсутствие внешних скриптов, изображений и шрифтов.

---

## 3. Открытие в браузере

- Отчёт открывается в браузере по умолчанию только при флаге `--open` (`-o`) в CLI или при `open: true` в `frontis.config`.
- Открытие работает кроссплатформенно:
  - Windows: `cmd.exe /c start "" <url>`
  - macOS: `open <url>`
  - Linux: `xdg-open <url>`
- При диагностическом запуске (код выхода 2) отчёт автоматически не открывается, путь выводится в консоль: `Диагностический отчёт: .frontis/report.html`.
- При сбое открытия браузера ошибка логируется в `stderr` с подсказкой пути к сохранённому файлу, не прерывая выполнение сбоем процесса.
