# Сверка версии Node.js с последней LTS

`createNodeVersionCollector(options)` находит версию Node.js проекта и сравнивает её с последней LTS из `https://nodejs.org/dist/index.json`. Версия Node.js, в которой запущен Frontis, здесь не используется: она есть в базовой информации о проекте.

## Источник версии

Берётся первый найденный источник:

1. `.nvmrc`;
2. `.node-version`;
3. `engines.node` в `package.json`.

В файлах учитывается первая непустая строка без комментария после `#`. Префикс `v` допускается.

| Значение | `kind` | С чем сравнивается |
| --- | --- | --- |
| `22.12.0` | `exact` | С самой версией |
| `22`, `^22`, `>=20`, `20.x \|\| 22.x` | `range` | С новейшим релизом, который подходит под диапазон. Так же неполную версию разрешает nvm |
| `lts/*`, `lts/latest`, `lts/<имя>` | `alias` | С новейшим релизом LTS-линии |
| `node`, `stable`, `latest`, `current` | `alias` | С новейшим релизом |

`lag` равен `major`, `minor` или `patch`, если версия для сравнения ниже последней LTS, и `null`, если не ниже. `allowsLatestLts` показывает, допускает ли значение саму последнюю LTS: для диапазона `^22` это `false`. При отставании есть одна находка `node-<lag>-behind` уровня `error`, `warning` или `info` с файлом-источником.

## Список релизов

Ответ сохраняется в `.frontis/cache/node-releases.json` (путь меняется опцией `cacheFile`) и сутки используется без запроса к сайту. Если сайт недоступен, используется устаревший кэш с `releases: 'stale-cache'`. Без кэша и сети проверка возвращает «Нет данных», остальные проверки продолжаются. Запрос ограничен 10 секундами.

| `status` | `code` | Когда |
| --- | --- | --- |
| `ok` | | Версия найдена и сравнена |
| `no-data` | `no-node-version` | Нет ни одного источника версии |
| `no-data` | `invalid-node-version` | Значение не разбирается или под него нет релиза |
| `no-data` | `node-releases-unavailable` | Нет ни ответа сайта, ни кэша |
